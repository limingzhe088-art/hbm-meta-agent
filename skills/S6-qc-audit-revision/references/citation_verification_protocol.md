# 文献链核验协议（Citation Verification Protocol）

> **用途**：核验"正文引用 ↔ 文献库记录 ↔ 真实发表信息"三者的逐条一致，产出字段级修改清单。
> **配套脚本**：`scripts/verify_dois.py`、`scripts/citation_crosswalk.py`
> **教训来源**：本项目在投稿前发现 4 条文献内容错误（年份/卷/页/DOI 错）、108 条库记录含大量重复、1 条正文引用在库中缺失。

---

## 1. 三条链必须逐条对上

```
正文引用（author, year）
        ↕  ①
文献库记录（EndNote / Zotero）
        ↕  ②
真实发表信息（Crossref / DOI）
```

| 链 | 检验内容 | 失败表现 |
|---|---|---|
| **① 正文 ↔ 库** | 每个正文引用在库中有唯一对应记录 | 引用查不到 / 一对多 |
| **② 库 ↔ 真实** | 年份、卷、期、页、DOI、期刊名正确 | DOI 解析到**不同**文章；卷页错 |
| **③ 库内部** | 无重复记录；机构作者字段正确 | 同一文献多条记录；作者字段致引用乱码 |

---

## 2. ① 正文引用 ↔ 库记录对照

### 2.1 做法

```
① 从稿件提取全部正文引用（作者-年份制或编号制）
② 归一化引用键：第一作者姓氏小写 + 年份
③ 在库中查找匹配记录
④ 分类：
   MATCHED      找到唯一匹配
   MISSING      库中无对应记录
   AMBIGUOUS    一对多（需消歧）
   UNUSED       库中有、正文未引用（可能应删除）
```

### 2.2 常见问题与处置

| 问题 | 表现 | 处置 |
|---|---|---|
| 同姓同年多篇 | `(Zhang, 2024)` 对应两篇 | ★ **后缀自动分配**：脚本为同 `(surname, year)` 的库记录按稳定顺序分配 `a`/`b`/`c`…；正文写 `(Zhang, 2024a)` → **精确命中**；正文未加后缀 → 仍标 `AMBIGUOUS` 并提示按库中顺序加后缀 |
| 机构作者 | `(EFSA, 2009)`、`(NRC, 2001)` | 库中作者字段须为机构全称，否则样式输出的缩写会乱 |
| 大小写不一致 | 正文 `(smedley, 2002)` vs 库 `Smedley` | 仅影响显示；仍应统一 |
| 引用未使用 | 库中有但正文未引 | 从库删除或标注为未使用（否则参考文献表会多出条目） |
| 正文引用库中无 | `MISSING` | ★ 必须补建记录，否则后续自动插入失败 |

### 2.2 ★ 后缀分配的稳定性

后缀分配必须**可复现**（同一输入两次运行结果相同）。实现规则（`citation_crosswalk.py::assign_suffixes`）：

| 规则 | 说明 |
|---|---|
| `library_order`（默认） | 按库中记录顺序。**调用方必须先按 `record_id` 排序**，否则顺序变化会导致后缀互换 |
| `record_id` | 按 `record_id` 字符串排序 |
| `title` | 按标题字母序 |

**自检已覆盖的边界**：
- 顺序稳定 → 后缀稳定
- 顺序反转 → 后缀互换（**证明"必须先排序"这一前提是必要的**，不是可选优化）
- 单一记录不分配后缀
- 库中缺同姓同年另一条时仍可命中（不会因消歧失败而漏匹配）

**本项目实证**：
- 正文 34 个唯一引用，33 个在库中匹配，1 个（`EFSA, 2014`）缺失 → 需补建
- 库中 108 条记录实际只对应 34 条唯一文献 → 需大规模去重

## 3. ② 库记录 ↔ 真实发表信息（DOI 核验）

### 3.1 做法

```
对库中每条记录：
  ① 取 DOI（若有）
  ② 调 Crossref API：https://api.crossref.org/works/{doi}
  ③ 比对：标题 / 期刊名 / 年份 / 卷 / 期 / 页
  ④ 分类：
     VERIFIED     全部一致
     MISMATCH     字段不一致（列出差异）
     DOI_INVALID  DOI 解析失败或解析到不同文献
     NO_DOI       无 DOI（需人工核验）
```

### 3.2 比对的字段与容差

| 字段 | 容差 | 说明 |
|---|---|---|
| 标题 | 前 30 字符不区分大小写匹配 | 副标题/标点差异不视为错误 |
| 期刊名 | 允许缩写与全称差异 | `Environ Health Perspect` vs `Environmental Health Perspectives` |
| 年份 | 精确 | 常见错误点 |
| 卷 / 期 / 页 | 精确 | 常见错误点 |
| DOI | 必须能解析 | |

### 3.3 本项目实证（4 条内容错误）

| 文献 | 字段 | 库中现为 | 应为 |
|---|---|---|---|
| Castriota 2022 | Year / Volume | 2020 / 128 | **2022 / 130** |
| Shen 2016 | Journal / Volume / Pages / DOI | Arch Toxicol / 90 / 2721-2733 / `10.1007/s00204-015-1659-6`（无效） | **Int J Environ Res Public Health / 13 / 205 / `10.3390/ijerph13020205`** |
| Yu 2007 | Journal / Volume / Pages | Environmental Pollution / 150 / 306-324 | **Environ Health Perspect / 115 / 636-642** |
| Zhang 2024a | Pages | 673-683 | **766-775** |

**注意 Shen 2016 的严重性**：库中记录指向了一篇**完全不同的文章**（Archives of Toxicology 的一篇），而 DOI 无效。这类错误用"人工看一遍"很难发现，必须靠 DOI 解析。

### 3.4 使用注意

| # | 注意 |
|---|---|
| 1 | Crossref 需要网络；离线环境降级为"仅做正文↔库对照" |
| 2 | 应设置 User-Agent（含联系方式），避免被限流 |
| 3 | 批量核验要控制速率；失败项重试后再判 `DOI_INVALID` |
| 4 | **核验结果只是证据**，字段修改仍由人工确认（可能库中信息来自出版社更正） |
| 5 | 无 DOI 的文献（书籍、标准、报告）必须人工核验 |

## 4. ③ 库内部去重与字段规范

### 4.1 重复检测

```
键 = 归一化DOI（优先） 或 归一化(第一作者姓氏 + 年份 + 标题前 30 字符)
```

| 重复程度 | 本项目实例 | EndNote 操作 |
|---|---|---|
| 6 条重复 | Nigra 2017、Nigra 2025、Smith 1998、Smith 2009、Sun 2004、Sun 2011 | `References → Find Duplicates`，逐对提示 → 保留信息最全者 |
| 3 条重复 | 其余 28 条 | 同上 |

**要求**：**每个副本都要改**，或先用 `Find Duplicates` 合并后只改保留的那条。
（否则改了副本 A、实际引用副本 B，问题依旧。）

### 4.2 字段规范

| 字段 | 规范 |
|---|---|
| 机构作者 | `European Food Safety Authority`、`National Research Council`（全称，样式会自动缩写） |
| 作者分隔 | 分号 `;` 分隔（EndNote 标准） |
| 期刊名 | 统一为一种形式（全称或缩写），与目标期刊要求一致 |
| 年份 | 4 位数字 |
| DOI | 纯 DOI 字符串，不带 `https://doi.org/` 前缀 |

## 6. 何时执行

| 时点 | 范围 |
|---|---|
| 初稿完成 | ① 正文↔库对照（必做） |
| 投稿前 | ② DOI 核验（必做）+ ③ 去重（必做） |
| 返修时 | 新增文献的核验 + 全库复查 |
| 收到审稿人质疑引用错误 | 立即全量重做 |

**本项目实证**：正是投稿前这一轮核验发现了 4 条内容错误与大量重复；若未做，审稿人极可能指出（本项目也确实收到了 R3-7"引用错配"）。

---

## 7. 人工裁决要求

| 待决项 | 人工动作 |
|---|---|
| 每个 `MISMATCH` | 采信 Crossref / 保留库中值（并注明原因） |
| `DOI_INVALID` | 查出版社页面手工确认 |
| `NO_DOI` | 人工核验 |
| 重复记录的保留选择 | 选信息最全的一条 |
| `UNUSED` 记录 | 删除 / 保留 |
| `AMBIGUOUS` | 消歧（加 a/b 后缀） |

**AI 不得自行**：删除库记录、改写 DOI、决定保留哪个副本。

---

## 8. 纪律（五条）

| # | 纪律 |
|---|---|
| 1 | **三个链都要查**：只查 DOI 不够（正文引用可能对不上库） |
| 2 | **重复必须全部副本处理**，只改一个等于没改 |
| 3 | **DOI 无效 ≠ 文献不存在**：可能是手写错误，须查证 |
| 4 | **改库与改稿必须同步**：库改了稿没改（或反之）仍会出问题 |
| 5 | **核验结果留档**，随投稿文件集版本化 |
