# 数值审计协议（Number Audit Protocol）

> **用途**：以"**快照 + 冻结分期 + 加权公式**"重算稿件中的每一个数字，输出差异表与连带修改清单。
> **配套脚本**：统一的 `scripts/audit_numbers.py`
> **教训来源**：本项目三条审稿意见（R1-3 相关系数与 P 值不匹配、R2-2 时段 GM 过时、R3-1 分期不统一）全部源于同一根因——**稿件数字与数据分析脱钩**。

---

## 1. 核心原则

### 1.1 唯一事实来源

```
快照（sha256 固定）  +  冻结配置（config_version 固定）  +  确定性脚本
                              ↓
                     任何一个正文数字
```

**硬规则**：正文中出现、但无法追溯到"快照某一行 + 配置某一条"的数字 = **孤儿数字**，不允许存在。

### 1.2 为什么不能靠人工核对

本项目的实际情形：手稿时期的数值基于**早期数据快照**，而分析脚本已跑到更新的快照。人工核对能发现"单个数字不对"，但**发现不了"整批数字系统性过时"**——后者在返修阶段才被审稿人指出，代价是整轮重写。

**审计脚本的价值**：把"逐个人工比对"变成"全量自动重算 + 差异分类"。人工只审差异项。

---

## 2. 审计流程

```
① 读取成果物（稿件或结果表）
② 提取其中所有数值（含单位、上下文句）
③ 识别数值类型（时段加权 GM / 地区 GM / 省级值 / EDI / 相关系数 / 计数）
④ 按类型用对应脚本从快照重算
⑤ 逐项比对 → 分类为 OK / MISMATCH / STALE_MANUSCRIPT / NO_SOURCE
⑥ 对 MISMATCH 与 STALE_MANUSCRIPT，定位**连带需修改的叙述**
⑦ 产出对照表 + 待人工裁决清单
```

**关键：第 ③ 步必须做类型识别**。同一个数字在不同句子里有不同含义（"32.58"可能是尿砷 1980-2000 的月度值，也可能是某省的值）。类型识别错误会导致"假 MISMATCH"。

---

## 3. 状态定义（四类，互斥）

| 状态 | 含义 | 触发条件 | 处置 |
|---|---|---|---|
| `OK` | 重算值与稿件值一致 | 差值在容差内 | 无需处理 |
| `MISMATCH` | 能追溯来源，但值不同 | 快照哈希一致，值不一致 | ★ **人工裁决**：采信重算值 / 修正换算 / 保留并注明 |
| `STALE_MANUSCRIPT` | 稿件基于**旧快照** | 稿件引用的快照哈希 ≠ 当前快照哈希 | ★ 必须全量重算并更新正文 |
| `NO_SOURCE` | 追溯不到来源 | 无匹配的快照行/配置项 | ★ **人工裁决**：补来源或删除该数字 |

### 容差规则

| 数值类型 | 容差 | 理由 |
|---|---|---|
| 加权 GM / 浓度 | 相对 0.5% | 浮点与舍入 |
| 百分比 / 降幅 | 绝对 0.5 个百分点 | 分母口径差异 |
| 相关系数 `r` | 绝对 0.001 | 与 P 值联动，须同时核对 |
| 计数（研究数/记录数/参与者） | 精确匹配 | 计数不可有舍入 |
| P 值 | 不比较具体值，只比较**显著性方向**与量级 | 不同软件算法差异 |
| EDI | 相对 1% | 参数舍入 |

---

## 4. 数值类型与重算方法对照

| 类型 | 识别线索 | 重算方法 |
|---|---|---|
| 时段加权 GM | 句含"during YYYY-YYYY"或"in the 2000s" | `weighted_gm.py` 按 `period_scheme` 分层 |
| 地区加权 GM | 句含大区名 | `weighted_gm.py` 按 `region` 分层 |
| 省级值 | 句含省名 | `weighted_gm.py` 按 `province` 分层 |
| 人群分层 GM | 句含 adults/minors/pregnant | `weighted_gm.py` 按 `population_group` 分层 |
| EDI | 句含 `μg/kg bw/day` | `edi_calculation.py` |
| 降幅百分比 | 句含"decrease/reduction of X%" | 由两个时段值算出**并核对分母** |
| 相关系数 + P | 句含 `r_s`、`P =` | 从 SPSS 输出或由原始数据重算；**须核对 r 与 P 的显著性一致性** |
| 计数 | 句含 `n =`、`studies`、`records` | 从快照计数；**须核对是记录数还是参与者数** |
| 质量评分分布 | 句含 high/moderate/low quality | 从质量评分表计数 |

---

## 5. 连带修改定位（审计的真正难点）

数值改了，**叙述往往也必须改**。本项目实证：

| 数值变化 | 连带必须修改的叙述 | 实例 |
|---|---|---|
| 时段 GM 变化 | 趋势描述、降幅百分比、摘要、结论 | "持续下降"→"下降—回升—稳定"；64%→62% |
| 地区排序变化 | 地区比较句、"最高/最低"表述 | "华南/华中较高"不成立 → 改为"西南最高" |
| 某地区数据补齐 | "no data"表述 | 尿砷原缺西北 → 排序重排 |
| 分期边界变化 | 所有时段标签与数值 | `1980-1999` → `1980-2000`（影响 15 条记录） |
| 计数口径变化 | `participants` → `participant records` | R3-2 |
| 公式修正 | 所有下游 EDI 值 + 结论表述 | 血路 EDI 公式修正 → 6.54/5.11/3.36 |

**审计输出必须包含"连带修改"列**，定位到**具体句子**（段落 + 原句），而非只报数字差异。

### 检索连带修改的方法

1. 原文数字 → 找到其在稿件中的**所有出现位置**（摘要、正文、图注、表注、结论）
2. 对每个位置，提取所在**整句**
3. 判定该句是否含**比较级/趋势/最高级**表述（`higher than`、`declined`、`highest`、`no data`）
4. 含则列入连带修改清单

> 摘要与结论是最高风险区——它们复述正文数字却常被遗漏更新。

---

## 6. 快照漂移检测

```
若 稿件的 snapshot_sha256 ≠ 当前快照 sha256
    → 全部相关数字标记 STALE_MANUSCRIPT
    → 不逐个人工核对，直接全量重算
```

**这是机制层面的根治**：本项目"稿子数值与数据快照不同步"的问题，靠"更仔细的人工核对"无法解决，只能靠哈希绑定。

**要求**：稿件内（或伴随的过程文档中）必须记录其绑定快照的 `snapshot_tag` 与 `sha256`。

---

## 7. 输出格式

`templates/02_number_audit.md` 结构：

| 列 | 内容 |
|---|---|
| `#` | 序号 |
| 数值类型 | 时段 GM / 地区 GM / EDI / 相关 / 计数 |
| 稿件原值 | 原样抄录（含单位） |
| 重算值 | 脚本输出 |
| 差值 | 相对或绝对 |
| 状态 | OK / MISMATCH / STALE_MANUSCRIPT / NO_SOURCE |
| 来源 | `snapshot_tag` + 分层条件 + 生成脚本 |
| 连带修改 | 需修改的句子（段落 + 原句 + 建议改法） |
| 人工裁决 | 空白待填 |

**附加产出**：`03-差异汇总.md`（按状态与类型统计）+ 待人工裁决包（结构化，见 `agent/routing.md` §3.5）。

---

## 8. 人工裁决要求

**AI 不得自行决定**以下事项，只能给建议与证据：

| 待决项 | 人工动作 |
|---|---|
| 每个 `MISMATCH` | 采信重算值 / 修正换算 / 保留并注明 |
| 每个 `NO_SOURCE` | 补来源 / 删除数字 |
| `STALE_MANUSCRIPT` 的重算范围 | 批准重算范围与分期口径 |
| 连带修改的措辞 | 审定最终表述 |
| 是否修订结论 | 由人工判断 |

**定稿门禁**：全部 `OK`（或 `MISMATCH`/`NO_SOURCE` 已逐条裁决完毕）方可定稿。

---

## 9. 审计纪律（五条）

| # | 纪律 |
|---|---|
| 1 | **每个数字都要审**，不抽样。抽样会漏掉系统性漂移 |
| 2 | **先查快照哈希**，再查数值。哈希不匹配时逐值比对无意义 |
| 3 | **区分"数字错"与"口径错"**。同一公式不同分期得到的差异不是计算错误 |
| 4 | **摘要与结论必须并入审计范围**（最高风险遗漏区） |
| 5 | **审计报告随稿件一起版本化**，不得覆盖旧版 |

## 10. 与 R 实现的对应

原项目 `_tmp/audit_numbers.py` 为单次分析脚本（硬编码快照路径、分期写死、只输出时段/地区/省份三类值）。
本工作包的 `audit_numbers.py` 在其基础上改为：

| 改进 | 说明 |
|---|---|
| 路径参数化 | `--input` / `--snapshot` / `--config` / `--out` |
| 分期从配置读 | 零字面量 |
| 类型自动识别 | 按线索正则匹配数值类型 |
| 四状态分类 | 增加 `STALE_MANUSCRIPT` 与 `NO_SOURCE` |
| 连带修改定位 | 输出所在句子 |
| 自检 | `--self-test` 用合成用例验证四类状态均可被检出 |
